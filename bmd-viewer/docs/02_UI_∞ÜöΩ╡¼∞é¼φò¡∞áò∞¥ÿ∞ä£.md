# UI 요구사항 정의서 — BMD Viewer

문서 버전: 1.0
작성일: 2026-06-25

---

## 1. 개요
본 문서는 의사가 환자의 골밀도 측정 결과를 확인하는 화면의 구성과 동작을 정의한다. 화면은 임상 환경에 맞춰 명료함과 데이터 정확성을 최우선으로 하며, 불필요한 장식을 배제한다.

## 2. 사용자 및 사용 맥락
사용자는 의사다. 의사는 진료 중 또는 판독 시 환자를 찾아 X-ray를 업로드하고, 분석된 L4 골밀도와 그 근거, 그리고 시간에 따른 변화를 확인한다.

## 3. 화면 구성 (전체 레이아웃)

대시보드는 좌측부터 3개의 열로 구성된다. 첫째 열은 환자 리스트와 검색, 둘째 열은 선택된 환자의 X-ray 이력과 골밀도 추세 차트, 셋째 열은 선택된 X-ray의 분석 결과 뷰어다.

```
┌──────────────┬───────────────────┬──────────────────────────┐
│ 환자 리스트   │ 환자 상세          │ X-ray 분석 뷰어            │
│ + 검색        │  - X-ray 이력      │  - 원본 X-ray + 척추 오버레이│
│               │  - BMD 추세 차트   │  - L4 BMD 값                │
│               │                   │  - XAI 판단 근거            │
└──────────────┴───────────────────┴──────────────────────────┘
```

## 4. 화면별 상세 요구사항

### 4.1 환자 리스트 (UI-01)
환자 리스트는 담당 환자를 목록으로 보여준다. 상단에 검색 입력란이 있으며, 이름 또는 환자번호(MRN)로 실시간 검색한다. 각 항목은 환자 이름, MRN, 성별, 최근 골밀도 값, 누적 X-ray 건수를 표시한다. 항목을 선택하면 해당 환자가 활성화되고 둘째 열이 갱신된다. 검색 결과가 없으면 빈 상태 메시지를 표시한다.

### 4.2 환자 상세 — X-ray 이력 (UI-02)
환자를 선택하면 상단에 환자 이름과 MRN이 표시되고, 그 아래 X-ray 이력이 최신순으로 나열된다. 각 이력 항목은 업로드 일자, 처리 상태(대기/분석 중/완료/실패), 그리고 완료된 경우 BMD 값을 표시한다. 상단에는 DICOM 업로드 버튼이 있다. 업로드 중에는 진행 표시를 보여주고, 추론이 진행 중인 항목은 상태를 자동 갱신한다.

### 4.3 X-ray 분석 뷰어 (UI-03)
이력에서 X-ray 한 건을 선택하면 셋째 열에 분석 결과가 표시된다. 좌측에는 원본 X-ray 영상이 표시되고, 그 위에 추출된 척추들이 경계 상자로 오버레이된다. 골밀도 측정 기준인 L4는 다른 척추와 시각적으로 구분(강조 색상)하여 표시한다. 추론이 진행 중이면 "분석 중" 상태를, 실패 시 실패 사유를 표시한다.

### 4.4 L4 골밀도 표시 (UI-04)
분석 결과 영역 상단에는 L4 골밀도 값이 큰 글씨로 강조되어 표시된다. 함께 T-score(가능한 경우), 모델 신뢰도, 사용 모델 버전, 노출 보정 여부를 보조 정보로 표시한다. 골밀도 값이 L4 측정값임을 라벨로 명확히 한다.

### 4.5 XAI 판단 근거 (UI-05)
골밀도 값 아래에는 XAI 패널이 위치한다. 이 패널은 골밀도 값에 영향을 준 항목들을 기여도 순으로 정렬하여 표시한다. 각 항목은 사람이 이해할 수 있는 라벨, 기여 방향과 크기(막대 + 부호 있는 수치), 그리고 보조 설명을 포함한다. 골밀도를 높인 요인과 낮춘 요인을 색상으로 구분하여 의사가 직관적으로 판단 근거를 파악할 수 있게 한다.

### 4.6 골밀도 추세 차트 (UI-06)
둘째 열 하단에는 해당 환자의 L4 골밀도 변화를 보여주는 선형 차트가 표시된다. 가로축은 측정 시점, 세로축은 골밀도 값이다. 누적된 측정값이 시간순으로 연결되며, 최초 대비 최신 측정의 변화량(절대값 및 백분율)을 차트 상단에 요약 표시한다. 골다공증 판단 참고선을 함께 표시하여 임상적 맥락을 제공한다. 측정 데이터가 없으면 빈 상태 메시지를 표시한다.

## 5. 상태 및 피드백
처리 상태는 대기, 분석 중, 완료, 실패의 네 가지로 구분하여 색상 배지로 표시한다. 분석 중 상태는 자동 갱신되어 완료 시 별도 새로고침 없이 결과가 나타난다. 실패 시에는 사유를 표시하고 재업로드를 안내한다. 오류 메시지는 무엇이 잘못되었고 어떻게 해결하는지를 인터페이스의 목소리로 안내한다.

## 6. 접근성 및 반응형
키보드 포커스가 시각적으로 드러나야 하며, 모바일 화면까지 무리 없이 축소되어야 한다. 동작 감소(reduced motion) 설정을 존중한다.

## 7. 카피 원칙
모든 라벨과 버튼은 시스템 구현이 아니라 사용자가 인식하는 대상의 이름으로 작성한다. 동작 버튼은 수행 결과를 그대로 말한다(예: "DICOM 업로드"). 골밀도 값에는 항상 L4 기준임을 함께 표기한다.
