# 프론트엔드 요구사항 정의서 — BMD Viewer

문서 버전: 1.0
작성일: 2026-06-25

---

## 1. 개요
프론트엔드는 React(Vite) + TypeScript로 구현하며, 의사가 환자와 X-ray 분석 결과를 확인하는 화면을 제공한다. 초기 데이터 백엔드는 REST(FastAPI + SQLite)이지만, 추후 Firebase로 교체할 수 있도록 데이터 계층을 추상화하고, 다른 프로젝트에 이식하기 쉽도록 기능 단위로 모듈화한다.

## 2. 기술 요구사항
빌드 도구는 Vite, 언어는 TypeScript(strict)다. 서버 상태 관리는 React Query를 사용하고, HTTP는 axios, 차트는 Recharts를 사용한다. 경로 별칭(@/)으로 모듈 참조를 단순화한다.

## 3. 아키텍처 및 모듈 구조

소스는 기능 단위로 분리한다. `features/` 아래에 patients, xray, bmd, auth 모듈을 두고, 각 모듈은 자신의 컴포넌트와 API 훅을 포함한다. 공통 요소는 `lib/`(타입, 데이터 계층, API)와 `components/`(UI, 레이아웃)에 둔다. 이 구조 덕분에 특정 기능을 폴더째 다른 프로젝트로 이식할 수 있다.

### 3.1 데이터 계층 추상화 (핵심)
모든 데이터 접근은 `lib/data/provider.ts`의 `DataProvider` 인터페이스를 통해서만 이뤄진다. 현재는 `RestDataProvider`(REST/SQLite) 구현을 사용하며, 추후 동일 인터페이스를 구현하는 `FirebaseDataProvider`로 교체하면 화면 컴포넌트를 변경하지 않고 백엔드를 전환할 수 있다. 어떤 구현을 사용할지는 환경변수(VITE_DATA_PROVIDER)로 결정한다.

컴포넌트는 데이터 제공자를 직접 호출하지 않고 React Query 훅(`features/patients/api/queries.ts`)을 통해서만 데이터에 접근한다. 이로써 캐싱, 폴링, 무효화 로직이 한 곳에 모인다.

## 4. 화면 및 컴포넌트 요구사항

### 4.1 환자 리스트 (PatientList)
담당 환자를 목록으로 표시하고 이름/MRN으로 검색한다. 각 항목은 이름, MRN, 성별, 최근 골밀도, 스터디 수를 보여준다. 선택 시 상위로 선택 이벤트를 전달한다.

### 4.2 X-ray 이력 (StudyHistory)
선택된 환자의 X-ray 이력을 최신순으로 표시하고, DICOM 업로드 버튼을 제공한다. 업로드는 mutation으로 처리하고 성공 시 이력을 무효화하여 갱신한다. 각 항목은 일자, 상태 배지, 골밀도 값을 표시한다.

### 4.3 X-ray 뷰어 (XrayViewer)
선택된 스터디의 원본 영상과 추출된 척추 오버레이, L4 골밀도, XAI를 표시한다. 추론 진행 중이면 자동 폴링하여 상태를 갱신하고, 완료 시 결과를 렌더링한다. L4 척추는 강조 색상으로 구분한다.

### 4.4 XAI 패널 (XaiPanel)
골밀도 값에 영향을 준 항목을 기여도 순으로 정렬하여, 라벨, 부호 있는 기여도, 막대, 설명과 함께 표시한다. 양/음 기여를 색상으로 구분한다.

### 4.5 골밀도 추세 차트 (BmdTrendChart)
환자의 L4 골밀도 시계열을 선형 차트로 표시하고, 최초 대비 최신의 변화율을 요약한다. 골다공증 판단 참고선을 함께 표시한다. 데이터가 없으면 빈 상태를 표시한다.

### 4.6 대시보드 (DashboardPage)
위 컴포넌트들을 3열 레이아웃으로 조립한다. 환자 선택 시 이력과 추세를 갱신하고, 스터디 선택 시 뷰어를 갱신한다.

## 5. 상태 관리 및 갱신
서버 상태는 React Query로 관리한다. 추론이 진행 중인 스터디는 일정 간격으로 폴링하여 완료 시 자동으로 결과를 반영한다. 업로드 성공 시 관련 쿼리를 무효화하여 목록을 최신화한다.

## 6. 인증
로그인 시 받은 JWT를 저장하고, 이후 모든 요청 헤더에 자동으로 포함한다. 인증 만료 시 재로그인을 안내한다. (데이터 제공자의 인터셉터에서 토큰을 주입한다.)

## 7. 환경 설정
API 기본 경로와 데이터 제공자 종류는 환경변수로 설정한다. 개발 시 Vite 프록시로 백엔드(/api, /derived)를 연결하여 CORS 문제를 회피한다.

## 8. 디자인 원칙
임상 도구로서 명료함과 데이터 정확성을 우선한다. 골밀도 값과 L4 기준임을 분명히 표기하고, 상태와 오류는 사용자가 다음 행동을 알 수 있도록 안내한다. 키보드 포커스와 반응형, 동작 감소 설정을 존중한다.

## 9. 배포
프로덕션 빌드는 정적 자산으로 생성되며, nginx 컨테이너에서 서빙한다. nginx는 SPA 라우팅을 처리하고 /api 및 /derived 요청을 백엔드로 프록시한다. Firebase로 전환 시에는 호스팅과 데이터 제공자 구현만 교체한다.
